The buffer reveal is one hint carrying three mechanics: residue, flush, and
compact. The player's own proposal, given twice:

- `+04:48` *"initially roll out KV cache and then we roll out flushing the context buffer and only flushing."*
- `+04:58` *"And then we either purchase, I think this is a purchase, compact context ability."*

## Bugs

### B1 — The transcript does not follow the tail *(regression, v0.18.0, mine)*

- `+02:38` *"However, the chat window is not scrolling down on its own."*
- `+02:43` *"It should always be scrolled down on its own."*
- `+02:46` *"I did not scroll it up."*
- `+02:49` *"It still didn't scroll down."*
- `+02:50` *"So I wonder if there's some kind of interaction with the overlays, either mechanical or thinking, that is affecting it."*

v0.18.0 made autoscroll conditional on `chatPinned`, which is recomputed from
the chat's `scroll` event. Setting `scrollTop` programmatically fires that
same event, so the renderer's own scroll can flip `chatPinned` to false and
autoscroll never runs again. Once false, nothing sets it back except reaching
the bottom by hand. The player's instinct — that an overlay was involved —
was close: any render is enough.

Fix: scroll events may only ever re-pin. Unpinning requires a real user
gesture.

### B2 — Submit reports nothing *(reported separately, same build)*

The submission worked — `submissions/2026-08-07/1786140152844-woho/` holds
both the 33 KB events file and the 7.5 MB recording — but the button gives
almost no sign of it. On success it swaps its own label to "submitted"; on
failure it writes a message into a sibling span. There is no progress state
during a multi-second, multi-megabyte upload, and no confirmation that
survives a list refresh.
